# إعداد توقيع APK لتحديثات صديق المزارع

يُبنى APK تجريبياً دون أسرار التوقيع حتى يمكن فحصه، لكن لا يُنشر تحديث داخل التطبيق إلا بعد إعداد مفتاح توقيع ثابت. لا تضع ملف JKS أو كلمات مروره في مستودع GitHub؛ المستودع عام.

## إنشاء مفتاح التوقيع مرة واحدة على جهاز المالك

على جهاز موثوق، أنشئ مفتاحاً طويل الصلاحية:

```powershell
keytool -genkeypair -v -keystore sadiq-almazare-release.jks -alias sadiq-almazare -keyalg RSA -keysize 2048 -validity 10000
```

احتفظ بملف `sadiq-almazare-release.jks` في مكان آمن مع نسخة احتياطية مشفرة. لا تنشئ مفتاحاً جديداً لكل إصدار؛ جميع تحديثات التطبيق يجب أن تستخدم المفتاح نفسه.

## إضافة أسرار GitHub Actions

من المستودع افتح Settings → Secrets and variables → Actions → New repository secret، وأضف:

- `ANDROID_KEYSTORE_BASE64`: محتوى ملف JKS بعد تحويله إلى Base64. في PowerShell:
  ```powershell
  [Convert]::ToBase64String([IO.File]::ReadAllBytes(".\\sadiq-almazare-release.jks"))
  ```
- `ANDROID_KEYSTORE_PASSWORD`: كلمة مرور ملف JKS.
- `ANDROID_KEY_ALIAS`: `sadiq-almazare` إذا استخدمت الأمر أعلاه.
- `ANDROID_KEY_PASSWORD`: كلمة مرور المفتاح.

بعد حفظ الأسرار، أعد تشغيل سير عمل **Build Android APK**. سيبني إصداراً موقعاً وينشره، ثم يفعّل إشعار التحديث داخل التطبيق.

## سلوك التحديث

- يفحص التطبيق `/app-update.json` ويقارن الإصدار بأرقام التطبيق الأصلي عبر Capacitor App.
- يظهر إشعار التحديث وزر تنزيل APK عندما يتوفر إصدار أحدث وموقع.
- يفتح زر التنزيل رابط إصدار GitHub في متصفح Android؛ يكمل Android التنزيل ويعرض للمستخدم خطوة تثبيت الحزمة.
- يتطلب Android موافقة المستخدم على تثبيت التحديث، وقد يطلب السماح بالتثبيت من مصدر التنزيل.

## تنبيه الانتقال من APK قديم

الإصدار السابق المنشور كان APK تجريبياً (Debug). إذا كان APK الموجود على هاتف المستخدم موقعاً بمفتاح مختلف، فلن يسمح Android بتثبيت الإصدار الجديد فوقه. لا تحذف النسخة القديمة قبل التأكد من النسخ الاحتياطي للبيانات المحلية؛ وقد يلزم تثبيت الإصدار الجديد مرة واحدة كتثبيت جديد. بعد اعتماد مفتاح التوقيع الثابت أعلاه، تستخدم كل الإصدارات اللاحقة المفتاح نفسه لتحديث سلس.
